# Crouch (hold `Ctrl` / `C`)

## Context

The game had no stance: everyone was 1.8 m tall at all times. Crouch adds the
standard FPS trade-off — give up half your speed for a smaller silhouette and a
lower eye, so low cover actually covers you.

## Decisions

**Key: `ControlLeft` *or* `KeyC`, hold to crouch.** Both are always live. `C`
exists because holding Ctrl and pressing W is `Ctrl+W` in Chrome/Edge, which
closes the tab and cannot be stopped by `preventDefault()`. Ctrl is kept because
it is what players reach for.

**Crouch is a pose flag, not a `MoveInput` field.** It never touches the
movement collider (`playerAABB` stays `PLAYER_HEIGHT` tall), so `stepPlayer`
does not need to know about it, and there is no stand-up ceiling check to get
wrong. Its only movement effect is a speed multiplier, applied the way the sword
charge and flag carry already are: `game.ts` folds it into `speedScale`, which
scales `forward`/`strafe` before `stepPlayer`. What crouch does change is the
*combat* geometry, so it rides on the pose:

- `PlayerPose.crouch?: boolean` (shared; absent = standing, which is what bots send)
- `crouch: boolean` on `PoseMsg`/`ShootMsg`/`ThrowMsg`/`SwingMsg` — the attack
  messages need it too, because the server builds the attacker's eye/muzzle from
  the pose inside the attack message
- `PlayerSchema.crouching` — continuously-synced per-player fact, so it goes
  through the schema (like `charging`/`reloading`), not an ad-hoc broadcast

**Crouched hitbox = proportional scale.** `s = CROUCH_HEIGHT / PLAYER_HEIGHT`
(= 2/3) multiplies all three band edges: legs 0–0.467, torso 0.467–0.9, head
0.9–1.2; half-widths unchanged. One factor, no second set of band constants to
keep in sync, and it matches the client visual exactly because that is the same
uniform Y squash.

**Client visual = one wrapper group.** The body parts moved into a `body` group
inside `Humanoid.group`, and crouch is `body.scale.y = s`. The alternatives were
worse: `setPose` re-asserts `legL/legR.position.y` every frame (a per-part squash
would be silently overwritten), the torso mesh is a constructor local rather than
a field, and scaling `Humanoid.group` itself would squash the nametag sprite,
which is parented to it.

## Numbers

| Constant | Value | Meaning |
| --- | --- | --- |
| `CROUCH_HEIGHT` | 1.2 | crouched hitbox top (movement collider stays 1.8) |
| `CROUCH_EYE_HEIGHT` | 1.02 | keeps the standing 0.18 head clearance |
| `CROUCH_SPEED_SCALE` | 0.5 | 2.75 m/s; slower than flag carry (0.75) and sword charge (0.7) |

- `shared/types.ts` — `PlayerPose.crouch?`

## Accepted simplifications

- Grenade blast target point stays at standing chest height (~1.02) — still
  inside a 1.2 m crouched body.
- Nametag *visibility* box (`nametagVisibility.ts`) stays standing-height, so a
  crouched player's tag can peek over low cover.
- Blood FX heights and the minimap line-of-sight eye stay standing-height.
- The `muzzle()` fallback in `game.ts` (only used when no gun prop is out) stays
  at `EYE_HEIGHT`.

## Gotchas found while building this

- `ArenaRoom.tickBots` calls `applyPose(p, phys)` with a `PlayerPhysState`, which
  has no `crouch` field. `applyPose` must coerce (`m.crouch === true`) rather
  than assign, or every bot would write `undefined` into a boolean schema field.
- Old clients that omit `crouch` parse as `false`, so the wire change is
  backwards compatible.

## Verification

`npm test`, `npm run build`, `npm run smoke` (MINESHOOT_TEST=1 server), plus two
browsers: hold `C` and check the camera drops smoothly, speed halves, the other
client sees a squashed model with a lowered nametag, and shots over a crouched
head miss.
