# Minimap with client-side fog of war

## Context

Players asked for a map in the corner: always show me and my team, show enemies only
where somebody on my side can actually see them, always show my own flag, and show the
enemy flag only once it has been spotted.

Everything the map needs is already on the wire. The room broadcasts every player's
pose to every client (`RoomState.players`, no `@filter`/`StateView` anywhere in
`packages/server`), the flags carry their own position and status, and both flag stands
come out of `generateWorldFor(mode, seed)`. So the feature costs **no new messages and
no new schema fields**, and adds nothing to latency — only a little client CPU.

The flip side: the fog is **cosmetic**. A client that reads its own memory still knows
where everyone is. That is exactly the trust model the nametags already have
(`game/nametagVisibility.ts`), and it is fine for a game played with friends. Making it
truly hidden would need server-side interest filtering, which is a much larger change and
would cost server CPU.

## Decisions

- **Vision rule**: 360° line of sight, no view cone and no distance cap. One eye-to-eye
  voxel ray (`raycastVoxels` over the exact segment) per observer→target pair. A target is
  revealed if *any* observer sees it — me or a living team-mate.
- **Enemy flag**: last-seen. On its stand it pins to the base (the status is already
  public via the score bar). Carried or dropped, it follows the flag while somebody sees
  it and otherwise stays, dimmed, on the last spot we know of. The pin resets to the base
  on every return. My own flag is always live.
- **Every mode.** In deathmatch/training there are no team-mates, so the observer list is
  just me and the map behaves like a personal radar; bots count as enemies.
- **North-up, fixed.** The terrain is baked once and blitted, the arenas are small enough
  to memorise, and CTF's 96×48 only reads well in a fixed landscape orientation. The self
  marker is a rotating arrow instead.

## Numbers

- Scale 2 CSS px per block: 64×64 arena → 128×128 px, 96×48 CTF map → 192×96 px.
- Vision sweep every `VISION_INTERVAL_MS = 150`; markers reuse the cached answer between
  ticks. Worst case (8v8 CTF) is 8 observers × (8 enemies + 1 flag) = 72 short-circuited
  rays per tick, ~480 rays/s of ≤150 DDA steps.
- Line of sight is taken from feet + `EYE_HEIGHT` (1.62) on both ends; the flag is probed
  at its position + 0.9 (roughly mid-pole).
- Top-left corner (`left: 14px; top: 12px`) — the only free one: timer is top-centre,
  ping and kill feed top-right, health bottom-left, weapon panel bottom-right.

## File map

- `packages/client/src/game/minimapModel.ts` — pure, DOM-free: `hasLineOfSight`,
  `visibleIds` (union over observers, nearest-first, short-circuiting), `updateFlagPin`
  (the last-seen state machine), `worldToMap`, `yawToMapAngle`, `terrainColor`.
- `packages/client/src/hud/minimap.ts` — the `Minimap` canvas widget: bakes the terrain
  from `columnTop`/`getBlock` once, blits + draws markers each frame, runs the vision
  sweep on its own tick, `dispose()` removes the canvas.
- `packages/client/test/minimapModel.test.ts` — 19 cases over the pure module.
- `packages/client/src/screens/game.ts` — destructures `bases`, constructs the widget
  against `hud.root`, feeds a `MinimapFrame` each frame, disposes it in `finish()`.
- `packages/client/src/hud/style.css` — the `.hud .minimap` block.

## Verification

- `npm test` — the new `minimapModel` cases plus the existing suites.
- `npm run build` — typecheck + production bundle.
- `npm run smoke` against a `MINESHOOT_TEST=1` server: the script fails on any
  `console.error`/`pageerror`, so a throwing minimap would break it.
- By eye: a CTF room for the flag pins and the fog, and `?offline` for the no-room path.
