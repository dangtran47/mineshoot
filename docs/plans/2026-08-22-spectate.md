# Spectate after death

## Context

A dead player used to free-look from the spot they died on, greyscale, until the server
respawned them. In team elimination that is the whole round: no mid-round respawn, so you
stare at your own corpse for up to a minute. The fix is the standard FPS one — watch
somebody else play until you are back.

Everything the feature needs is already on the client. Every player's pose (x/y/z, yaw,
pitch) is broadcast to everyone and already smoothed by `SnapshotBuffer`, and the camera
convention matches exactly: `LocalPlayer.syncCamera` writes
`camera.rotation.set(pitch, yaw, 0, 'YXZ')` from the same wire values `Humanoid.setPose`
feeds a remote head. So spectating is a **client-only** change: no message, no schema
field, no server rule. Combat stays server-authoritative; a spectator sends nothing.

## Decisions

- **First person, not a chase cam.** The point is to see what the other player sees. The
  interpolated pose is sampled at the same `now - INTERP_DELAY_MS` the humanoids render
  at, so the watched body and the camera never disagree.
- **Auto-enter after `SPECTATE_DELAY_MS` = 1500.** The death overlay ("YOU DIED", killer,
  badges) gets a moment on the death spot first, then the camera moves. Before that, and
  whenever no target is eligible, the old free-look death cam stays.
- **Team modes spectate team-mates only** (`ctf`, `td`); deathmatch and training spectate
  anyone alive, bots included. In a team mode without a team (`TEAM_NONE`) the list is
  empty, so the death cam holds.
- **LMB = next, RMB = previous.** Both are free while dead (`look.onMouseDown` already
  early-returns) and it is what CS/Valorant players expect. The mouse wheel is now gated
  on `local.alive` so a spectator no longer cycles their own weapons.
- **Keep the greyscale `.dead` filter and the respawn/round countdown.** They are how you
  know you are dead and when you are coming back; the spectate label is separate.
- **Ordering is by session id**, so next/previous is stable while the list churns.

## File map

- `packages/client/src/game/spectateModel.ts` — pure, DOM/three-free: `eligibleTargets`
  (alive, not me, team filter), `cycleTarget` (wraparound), `retainTarget` (keep the
  current target valid, else fall back), `spectateReady` (the 1.5 s gate).
- `packages/client/test/spectateModel.test.ts` — cases over the pure module.
- `packages/client/src/game/remotePlayers.ts` — `pose(id, now)` (interpolated pose at the
  render time) and `setHidden(id, hidden)` (a sticky hide that `snapshot()` respects, so
  the spectated body and its nametag stay out of their own camera).
- `packages/client/src/render/viewmodel.ts` — `setHidden(hidden)`: the whole view model
  group off while spectating (you are looking through someone else's eyes, not holding
  your own gun).
- `packages/client/src/hud/hud.ts` + `style.css` — `setSpectating(name)`, the bottom
  label with the controls hint.
- `packages/client/src/screens/game.ts` — the glue: target state, mouse cycling, the
  per-frame camera override after `local.update()`, cleanup on respawn.

## Verification

- `npm test` — the new `spectateModel` cases plus `pose`/`setHidden` in
  `remotePlayers.test.ts` and the view-model hide.
- `npm run build` — typecheck + production bundle.
- `npm run smoke` against a `MINESHOOT_TEST=1` server: players die during the run and the
  script fails on any console error, so a throwing spectate path breaks it.
- By eye, two windows on `make start`: die, wait ~1.5 s, land in the other player's view
  with their body and tag hidden; LMB/RMB cycle; respawn restores the view model and the
  camera. In `td` the spectate holds until the next round starts.
